# ADR 0045 — Project 6: the deliverables, and what becomes public

**Status:** accepted · 2026-10-21 · decided by Jose (Project 6, design call 6)
**Builds on:** ADR 0001 ("whether anything is split into a public showcase repo is a Project 6
decision"), the course boundary in `docs/practicum-handoff.md` §2 (no employer systems, data,
credentials or networks; coursework never described as work for the employer), ADR 0043 (the
résumé line is reworded at close to what is true).

---

## Context

The done-means is a stranger understanding the system from a README, with a diagram, a decision
record per model role, and a ninety-second recording. `agentic-lab` is private, and cannot simply
be made public: `docs/ai-command-center-plan.md` is private career planning, and `LOG.md` and the
handoff documents carry personal and boundary context that belongs in a private record.

## Options

- **A — A curated public showcase repo, split out at close.** README, diagram (as source),
  the ADRs that explain the system, evidence summaries and code — no LOG, no handoff documents, no
  employer references. A scrub step checks for credentials and employer names; Jose approves file
  by file. `agentic-lab` stays private. The recording (the SRV01 promote playbook run) is linked.
- **B — Everything private,** shown on request.
- **C — Make `agentic-lab` public.**

## Decision — A

**Jose picked A** (multiple choice, Claude's recommendation marked): it turns five projects into
one thing a stranger can open, without publishing what the boundary exists to keep private.

## What this commits

- **The README** (in `projects/06-command-center/`, copied to the showcase root) is written for a
  stranger: what the system does, the job table, the promotion flow, a model table citing each
  role's measurement, one table of every exit code for every job, the 2026-09-05 org chart beside
  what Project 3 measured, and what is *not* claimed.
- **The diagram is source** (Mermaid in the README, so GitHub renders it and a diff shows a change),
  with an exported image for places that cannot render it.
- **The recording** is ≤ 90 s of the SRV01 promote playbook — a clean script promoted, a bad one
  rejected and SRV01 restored. Linked, not committed (size).
- **The showcase repo is built by a tool, not by hand-copying:** an explicit include list (never
  "everything except"), a scrub that fails on any credential pattern, employer name, personal
  path or lab password field, and a manifest of what was included. Jose creates the empty public
  repo on GitHub and runs the push; Claude cannot push (no route).
- **Nothing employer-related is ever included**, and the showcase README states the work was done
  on personal hardware against a personal lab.
- **The résumé line is rewritten at close** to what was built (ADR 0043), and the same wording is
  used in the showcase README.

## Known weaknesses, accepted

- **Two repos to keep in step.** The showcase is a snapshot regenerated by the tool, not edited
  directly; drift is fixed by re-running it.
- **A scrub catches patterns, not judgement.** Hence Jose's file-by-file approval before the first
  push.
- **Lab IP addresses and the `corp.lab` domain are published.** They are private-range lab values
  with no route from the internet; accepted, and named in the scrub's allow-list.

## Rejected

- **B.** The résumé line would point at nothing a reader can open.
- **C.** Publishes employer references and personal notes.

## Amendment 1 — 2026-10-23: the recording goes in pinned by hash

The showcase tool refused the recording, as built: it publishes only UTF-8 text it can scrub.
**Jose's pick (recommended):** `showcase/binaries.tsv` lists each binary allowed out, pinned by
its full sha256, with the reason. The person's frame-by-frame review is the scrub (OCR of sampled
frames, the host name masked on every frame; `evidence/build-step-07-recording.md`). A changed file
or a stale pin is a hit, and file-by-file approval still applies. Rejected: uploading through
GitHub's web editor (a file outside the built, approved set), and keeping the video private
(this ADR committed to linking it).
This supersedes "Linked, not committed (size)" above, because the cut is 1.4 MB. The recording shows
the bad script only (caught, restored, confirmed, exit 1). The clean script's promotion is run A
in `evidence/build-step-05-promote-on-srv01.md`, and a 90-second cut can't hold both runs clearly.
